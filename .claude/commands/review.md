작업 목표:
- 지정된 PR 번호 또는 현재 체크아웃된 브랜치의 변경사항을 리뷰 기준에 맞춰 검토한다.

입력:
- $ARGUMENTS 에 PR 번호 또는 리뷰 대상 정보가 들어온다.
- 예: `/review 123`

반드시 수행할 절차:
1. 인자가 PR 번호라면 해당 PR 정보를 조회한다.
2. 팀의 리뷰 기준 문서를 먼저 읽는다:
    - .claude/commands/shared/review-rules.md
    - 또는 팀이 지정한 review.md
3. 변경 파일, diff, 테스트 여부, 영향 범위를 확인한다.
4. 아래 우선순위로 리뷰한다:
    - 버그 가능성
    - 보안/권한 문제
    - 데이터 정합성
    - API 계약 변경
    - 예외 처리
    - 테스트 누락
    - 가독성/유지보수성
5. 코멘트는 중요도별로 구분한다:
    - must fix
    - should fix
    - nit
6. 근거 없는 취향성 지적은 줄이고, 재현 가능하거나 유지보수에 중요한 내용 위주로 작성한다.
7. 마지막에 전체 리뷰 요약과 머지 전 체크포인트를 정리한다.

제약:
- 확인하지 않은 사실을 단정하지 않는다.
- 스타일 지적만 과도하게 늘어놓지 않는다.
- 리뷰 기준 문서와 충돌하는 임의 규칙을 만들지 않는다.

출력 형식:
- "리뷰 요약"
- "Must fix"
- "Should fix"
- "Nit"
- "머지 전 체크포인트"
