작업 목표:
- GitHub 이슈를 생성하거나, 이미 주어진 이슈 설명을 바탕으로 작업 브랜치를 준비한다.

입력:
- $ARGUMENTS 에 작업 제목 또는 이슈 관련 설명이 들어올 수 있다.
- 인자가 비어 있으면 사용자에게 작업 목적, 배경, 완료 조건을 먼저 질문한다.

반드시 수행할 절차:
1. .github/ISSUE_TEMPLATE/ 아래 파일들을 확인하고 가장 적합한 템플릿을 선택한다.
2. 템플릿 형식에 맞춰 이슈 초안을 작성한다.
3. 사용자가 승인하면 GitHub 이슈 생성에 필요한 제목/본문을 정리한다.
4. 현재 git 상태와 현재 브랜치를 확인한다.
5. 최신 develop 브랜치 기준으로 새 feature 브랜치를 만든다.
6. 브랜치 이름은 팀 규칙에 맞게 `feature/{issue-number}-{short-summary}` 형식을 우선 사용한다.
7. 브랜치 생성 후 체크아웃한다.
8. 마지막에 아래 내용을 보고한다:
    - 이슈 제목
    - 핵심 요구사항 3줄 요약
    - 생성/사용한 브랜치명
    - 바로 다음 추천 액션

제약:
- 사용자의 명시적 확인 없이 push 하지 않는다.
- develop 이외의 기준 브랜치를 임의로 사용하지 않는다.
- 템플릿 필수 항목을 누락하지 않는다.

출력 형식:
- "이슈 초안"
- "브랜치 정보"
- "다음 단계"
